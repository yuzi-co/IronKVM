IronKVM 1.0.3 is an update package and a card image. Settings > Update takes the
package and needs no card.

This release is about the board coming back by itself. There are three layers of
recovery now, and the one that already existed had stopped working. The rest is
maintenance: the whole dependency tree moved to current majors, three advisories
closed with it, and what the build downloads is pinned.

## The boot watchdog had been standing down early

The watchdog that confirms a new root slot, or reverts to the last good one,
gave up ten seconds into every boot and confirmed the slot on evidence it had
not gathered. Its health test had two answers where it needed three: it read "no
carrier" as healthy, and eth0 has no carrier at the first sample.

Everything behind that test was therefore unreachable in practice: the
300-second deadline, the rollback of a boot script, and the fall back to the
recovery slot. No carrier is neither health nor a fault now, so the watcher keeps
waiting while that is the answer, and it leaves without confirming anything if
the deadline arrives with the question still open.

## The SoC watchdog is armed

Every other guard in this firmware is a process, and a process has to fork to
act. This board has two faults that leave nothing able to fork: memory pressure
that wedges process creation without the kernel ever choosing an OOM victim, and
a kernel-side lockup. There is no remote power cycle on this enclosure, so both
cost a trip to the board.

The hardware timer now covers that. It arms 42 seconds and is pinged every
eight, and the ping is not a bare timer reset: it asks the kernel for a megabyte
and touches it first, because a board that cannot hand out a megabyte is a board
that cannot fork.

A shutdown deliberately leaves the timer running. On 2026-08-15 this board ran a
whole shutdown and never reset, answering ping for 25 minutes with every port
refused, and only removing power ended it.

## The supervisor watches the ssh door

A board that serves video with a dead sshd looks healthy from a browser and
cannot be repaired from anywhere. The supervisor now judges that door on its
own. It probes the listener rather than the process, because a wedged sshd keeps
its pid and answers nothing, and a dead door never reaches the reboot ladder:
restarting a working KVM over a maintenance daemon is the worst trade available
here.

## Everything is on a current version

The web interface is built on antd 6, Tailwind 4, react-router 7, TypeScript 6
and ten other current majors. React stays at 18. The interface is deliberately
unchanged: the Tailwind step was taken as a port of the existing styling and not
as a redesign, so nothing should look or behave differently. On the device side
the WebRTC stack and six other Go dependencies are current too.

Three advisories closed with them. Two are react-router, an open redirect
through a backslash in a link, and constructor injection during server-side
rendering, which this product does not do. The third is an infinite loop on
invalid input in Go's text package, and it is the one this code actually
reaches: every outbound request resolves a proxy through the affected path, so
the update feed and the Tailscale download both cross it.

## Smaller things

The desktop page does less work when it opens, and the virtual keyboard derives
its layout instead of keeping a copy of it.

Everything the builder images download is now pinned and checked, and the
GitHub actions this repository runs are pinned to commits rather than to tags.

## Upgrading

Settings > Update takes the package. The card image is only needed for a fresh
board.

This release changes boot scripts: the hardware watchdog is a new one, and the
supervisor and the boot watchdog are both replaced. They take effect at the next
boot. Nothing changes in the USB descriptors or the kernel modules, so the
managed host sees nothing and the gadget is not rebuilt.

## Checksums

`SHA256SUMS` covers both files. It proves a download is intact. It is not
signed, so it does not prove who built it.
