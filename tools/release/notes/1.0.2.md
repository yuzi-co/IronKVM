IronKVM 1.0.2 is an update package and a card image. Settings > Update takes the
package and needs no card.

The headline is a USB gadget that repairs itself. Before this, a keyboard that
stopped working stayed stopped until somebody restarted the server or replugged
the cable, and nothing anywhere said so: the board keeps answering on the
network the whole time, so the web interface looks healthy while no keystroke
reaches the host.

## The gadget is supervised now

The server watches the USB controller for as long as it runs, and repairs the
link when it fails. Recovery used to run at exactly two moments, a guard in the
first seconds of boot and an operator pressing "reset USB", so a link that died
at any other time stayed dead.

Two details are worth knowing, because they decide what it will and will not do.

It counts a link that enumerated at **full speed** as a fault in its own right.
A full-speed link reports "configured" and does not work: the periodic bandwidth
in a full-speed frame does not hold three HID interrupt endpoints beside the
console, the disk and the speaker, so the host quietly stops polling some of
them. That is the failure behind a NanoKVM that comes up with a working mouse
and a dead keyboard.

It never resets the USB controller by itself. That operation can leave the
gadget wedged with no way back except a shell on the device, and this board has
no remote power cycle, so it stays behind the button in Settings where a person
is watching. The automatic ladder rebinds twice, rebuilds once, then stops and
says so rather than rebinding forever, because a KVM plugged into a computer
that is switched off looks exactly like a broken one.

## Two viewers no longer halve each other's video

Direct mode and WebRTC mode each ran their own read loop against a single
encoder. Two loops do not each receive the stream, they divide it, so a viewer
on each path got roughly every second frame of a group of pictures. That decodes
to nothing useful, and the board paid for the capture twice to produce it. The
frame rate the interface reported was double the frames actually captured, for
the same reason.

## Security

An anonymous caller could stop the server with one request. `POST
/api/auth/login` decrypts the request body before it checks any credential, and
two shapes of malformed password panicked the cipher underneath. Update if your
board is reachable from anywhere you do not control.

48 dependency advisories are closed, 16 in Go modules and 34 in npm packages.
Nearly all of them needed no more than a version the existing constraint already
allowed.

Logging in is also cheaper. A board with no account file rebuilt its default
database on every read, and that ran bcrypt at full cost each time, about a
second of a 1GHz core, on every request carrying a session. It is derived once
now.

## Also fixed

- A login that looped with nothing logged in. The session cookie took its Secure
  attribute from what the server offers rather than from how the request
  arrived, so a board set to HTTPS marked the cookie Secure on a plain HTTP
  reply and the browser never sent it back.
- A Japanese Zenkaku/Hankaku key that stuck down on the host. The browser can
  start a composition between that key's own keydown and keyup, so the keyup was
  dropped and the host kept the key held.
- USB audio repeating a fragment. Below eight isochronous requests in flight, a
  service interval the host does not use makes the kernel copy the same buffer
  into the audio ring twice, and the repeat is audible. The kernel default on
  this board is three.

## New

Horizontal scroll works in relative mouse mode. A tilt wheel or a thumb wheel
reaches the host now.

There is a boot-time CPU frequency setting.

## Upgrading

Settings > Update takes the package. The card image is only needed for a fresh
board.

This release changes the USB HID report descriptor, so the gadget is rebuilt on
the first boot after the update. Expect the host to re-enumerate the keyboard
and mice once.

## Checksums

`SHA256SUMS` covers both files. It proves a download is intact. It is not
signed, so it does not prove who built it.
