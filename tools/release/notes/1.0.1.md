IronKVM 1.0.1 installs on an 8 GB microSD card. The card image ends after the
recovery slot, and the device makes its data partition on the first boot, at
whatever size the card allows.

## The 1.0.0 card image is superseded

Do not flash 1.0.0. A board flashed with it has no data partition, so it keeps
the factory root password and loses its identity on a slot switch. 1.0.1 makes
`/dev/mmcblk0p6`, mounts it on `/data`, and binds `/etc/kvm` and `/root/.ssh`
from it. The password you set then outlives a reboot and a slot switch.

The download does not change with the card. 1.0.1 is 372.3 MB, the same as
1.0.0, because the space the data partition used to occupy was empty.

## What is fixed

- The card image now reports its own version. A board flashed with an earlier
  image reported the official application version, and the update page reads
  that with `semver.gte`, so it called a board that could take no update at all
  up to date.
- The board keeps its ssh host key. It is generated before `sshd` starts and
  stored on `/data`, so the other slot presents the same fingerprint instead of
  looking like a different machine.
- The H.264 encoder gives its carveout back when capture stops. A stop used to
  strand about 11.6 MB of the 75 MB ION reservation, and enough of them filled
  it until the board was rebooted.

## Upgrading

Settings > Update takes the package and needs no card. A board flashed with an
earlier 1.0.x image reports the wrong version and will not offer the update; on
that board, install the package once by hand and the version corrects itself.

## Checksums

`SHA256SUMS` covers both files. It proves a download is intact. It is not
signed, so it does not prove who built it.
