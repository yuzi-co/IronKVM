IronKVM 1.1.0 is an update package and a card image. Settings > Update takes the
package and needs no card.

This release is mostly about the video path. The capture loop stopped doing work
nobody asked for, the encoder is told the truth about its frame rate, and a
channel that stops handing out frames is rebuilt instead of waiting forever. It
also adds the setting people asked for most: a static IP address, set from the
web interface, with a way back if the address is wrong.

## A static IP address, and a way back from a wrong one

Settings > Network can now set the address, the subnet mask and the router
instead of only the DNS servers. The device-side mechanism has been there for a
long time, as a file on the boot partition that nobody could write without ssh.

Getting an address wrong on a device whose whole purpose is reaching a machine
you cannot otherwise reach is the kind of mistake that costs a walk to the rack,
so the change is applied on trial. IronKVM takes the new address, and then waits
three minutes for a client to reach it there. Opening IronKVM at the new address
and signing in is what keeps the change: signing in is the proof the trial was
waiting for, and there is no further button to find. If nobody reaches the
board, it puts the previous settings back by running its own boot script, so a
board that reverted and a board that rebooted end up in the same state. Nothing
is written to the boot partition until the change is kept.

Only a signed-in session counts, and only over the address the trial applied.
An api key belongs to a script, and a script that can reach the board says
nothing about whether you can. Loopback does not count either, because the
supervisor and the on-device agent both speak to the server that way without
crossing the network the change could break. Keep is still there for the case
where you reached the board over Wi-Fi or over the USB network gadget instead.

The deadline is held outside the server as well as inside it, so a server that
stops for any reason during those three minutes does not leave the board
stranded on an address nobody can reach. A server that restarts mid-trial still
reports the pending change, still accepts the confirmation, and is still kept by
the next client that signs in over the new address.

The panel is translated into all twenty-four languages.

## The video path

**Frames nobody could take are no longer read.** The MJPEG loop read on every
tick whether or not a viewer had drained the previous frame, and the frame was
then thrown away. Over HTTPS it read 30 frames a second while about 10 reached
the browser, so two reads in three were a cgo call and two 350KB copies for a
frame that was discarded. Measured at 1080p with one viewer, that was roughly
14MB/s of copying and 7MB/s of heap for nothing. The read rate now follows the
viewer instead of the clock.

**Frames identical to the one before are no longer sent.** The encoder runs at
fixed quantisation, so an unchanged screen produces byte-identical output and
comparing it is an exact test for "nothing happened". A still screen now costs
almost nothing on the wire. A viewer that arrives while the screen is still is
sent a frame immediately rather than waiting for the host to move, and a refresh
goes out every five seconds so a frame lost in transit cannot leave a stale
picture.

**The encoder is told the real frame rate.** Its rate control had been
configured with a frame rate it was not being fed.

**A wedged capture channel is rebuilt.** A VPSS channel that stops handing out
frames used to read like an absent HDMI signal and stayed that way until
somebody restarted the server; the channel is now rebuilt in place. Signal loss
no longer counts toward the wedge detector either, because a source that is
genuinely absent is not a fault.

**Fewer copies on both encode paths.** H.264 and MJPEG now encode from the frame
the hardware already holds rather than a mapped copy of it, the frame buffers
are kept instead of allocated per frame, and an MJPEG frame is mapped only when
something is about to read it.

**Streams recover on their own.** MJPEG asks for the stream again after a
failure instead of leaving a still picture, H.264 repairs a dropped stream with
a keyframe rather than with the next frame it happens to have, and WebRTC now
answers the retransmission requests the browser was already sending.

**HTTPS serves HTTP/1.1.** The HTTPS listener had HTTP/2 on by default, which
this workload cannot use and this processor cannot afford: measured at 1080p,
MJPEG carried 10.5MB/s over HTTP/1.1 and 3.5MB/s over HTTP/2, and the delivered
frame rate fell from 30 to about 10. It also broke the keyboard, because a
websocket cannot run on an HTTP/2 connection. HTTP/2 is now `http2:` in
`/etc/kvm/server.yaml`, off by default, for the deployment that needs it.

## The patched kernel module is loaded now

The video driver in the install package has carried a patch since 1.0.3 that
keeps four idle capture threads out of the load average. It had never been
loaded. The boot script read only the stock module directory, so the module
shipped, installed, and was overwritten by the stock one at every boot; a board
sitting idle reported a load average of about 4 while the processor was 90%
idle.

The script now takes each module from the install package first and falls back
to the stock copy if the packaged one will not load. That fix had a second half:
the image did not install the fixed script either, so it would have reached
nobody. Which boot scripts an image installs is now checked against the base
system before a release is built, and a script the fork has changed cannot be
left behind silently again.

## The OLED panel

The status page is drawn small and moves around the panel, so a fixed layout
cannot burn itself into one place, and it prefers the rows the previous page did
not use. Redrawing no longer blinks the panel. The address is shown even when
there is no route to a gateway. The panel brightness sits beside the sleep timer
in Settings. Two writers could drive the panel at once and produce a garbled
display; only one runs now, and the nudge stands down when the firmware owns the
panel.

## Smaller things

Sessions survive a server restart: the JWT secret is generated once and kept in
`/etc/kvm/.jwt_secret` instead of being new on every start.

One broken panel no longer takes the whole desktop with it, and neither does one
corrupt value in browser storage.

The screen settings you chose are served after a restart, rather than the
defaults.

The Go profiles are served under `/api/debug/pprof`, for an administrator
session or an administrator API key. They are always available, because a
profiler that needs a restart cannot see the problem the restart cleared.

The video menu says that audio needs WebRTC.

The USB role is read back after it is set, because writing it proves nothing.

The capture diagnostic was renamed so an application update cannot delete it.

## Upgrading

Settings > Update takes the package. The card image is only needed for a fresh
board.

**This release changes boot scripts, and two of them are installed into
`/etc/init.d` for the first time.** The kernel module loader is one: from the
next boot the video driver comes from the install package rather than the stock
directory. The packaged module was checked for interface compatibility, and a
module the kernel refuses falls back to the stock copy rather than taking the
video pipeline down. The wired and wireless network scripts are the other
change, and both now ask DHCP for classless static routes, which a flat network
will not notice.

The capture libraries are rebuilt in this release, so the video pipeline
restarts with the server. Nothing changes in the USB descriptors, so the managed
host sees no new device and the gadget is not rebuilt.

## Checksums

`SHA256SUMS` covers both files. It proves a download is intact. It is not
signed, so it does not prove who built it.
