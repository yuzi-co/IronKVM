# IronKVM 1.0 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Turn the fork into IronKVM 1.0: a named firmware distribution with published release artifacts, an update feed, a safe package install hook, and a written account of how it differs from the official Sipeed firmware.

**Architecture:** Three independent layers. The Go server gains an optional absolute download URL in the update manifest, a widened package name pattern, and a call to a package-supplied install hook. The device gains `install.sh`, which copies init scripts into `/etc/init.d` while keeping the originals, and a rollback in `S00awatchdog` that restores them after three boots with no success. The build host gains `tools/release/release.sh`, which produces the SD image, the tarball, the checksums and the feed manifest, verifies its own output, then publishes.

**Tech Stack:** Go 1.24 (gin, logrus), React + TypeScript + Vite, POSIX shell (BusyBox ash on the device), `mke2fs`/`debugfs` for images, `gh` for publishing.

**Spec:** `docs/specs/2026-08-16-ironkvm-distribution-design.md`

## Global Constraints

- The distribution is named **IronKVM**. Tagline, used verbatim: `IronKVM: hardened community firmware for the Sipeed NanoKVM. Not affiliated with Sipeed.`
- The rename is **shallow**. Do not change `/kvmapp`, `/etc/kvm`, `NanoKVM-Server`, `common/version`'s import path `NanoKVM-Server/...`, any API path, or `utils.SecretKey`.
- Version line is semver starting at `1.0.0`. Never encode the upstream version inside it.
- Package name pattern accepts `(nanokvm|ironkvm)_X.Y.Z.tar.gz`. An official Sipeed package must stay installable.
- Licence stays GPL-3.0. Upstream stays credited.
- Runtime state never goes under `/kvmapp`.
- No em dashes in any prose, commit message, or documentation this plan produces.
- English documentation follows ASD-STE100 where it fits, as `CLAUDE.md` requires.
- Go tests run off-device with the `novision` tag: `go test -tags novision ./...` from `server/`.
- Every guard added in shell gets a mutation test: break the guard, prove a test fails, restore it.

Replace the `joinUpdateURL` call at the end of `parseLatest` with:

```go
	resolved, err := resolveDownloadURL(latest.ManifestURL, baseURL, latest.Name)

// resolveDownloadURL decides where the package is fetched from.
//
// A manifest may name the package outright, which is what lets the manifest and
// the package live on different hosts. It must be absolute and it must be
// https: the sha512 that would catch a substituted package comes from this same
// document, so transport security is the only thing standing between the device
// and whatever is on the path.
//
// Naming the package grants no trust that the manifest did not already have. A
// hostile feed could always serve any bytes it liked from its own directory.
func resolveDownloadURL(manifestURL string, baseURL string, name string) (string, error) {
	if manifestURL == "" {
		return joinUpdateURL(baseURL, name)
	}

	parsed, err := url.Parse(manifestURL)
	if err != nil {
		return "", fmt.Errorf("invalid update package url: %w", err)
	}
	if parsed.Scheme != "https" {
		return "", errors.New("update package url must use https")
	}
	if parsed.Host == "" {
		return "", errors.New("update package url must be absolute")
	}

	return parsed.String(), nil
}
```

### Task 3: Run the package's install hook

**Files:**
- Modify: `server/service/application/install.go`
- Create: `server/service/application/install_test.go`

**Interfaces:**
- Consumes: nothing from Tasks 1 and 2.
- Produces: `var runInstallHook = execInstallHook`, a package-level variable tests replace. `installPreparedPackage(sourceDir string) error` keeps its signature and returns a wrapped error when the hook fails.

**Why the hook exists.** Nothing in `kvmapp` copies `kvmapp/system/init.d/*` into `/etc/init.d`. Only the image manifest does. Without this, a release would ship the fork's boot behaviour in the SD image and silently omit it from the tarball.

**Why a hook failure still reports failure.** `installPreparedPackage` runs after `applyUpdate`, which does its own restore on its own failure. Returning an error here does not undo the application install, and the caller turns it into `update failed: <message>` for the user. An application that updated while its boot scripts did not is a partial failure the operator has to know about.

```go
// stubInstallHook records whether the hook ran and lets a test make it fail.
func stubInstallHook(t *testing.T, err error) *int {
	t.Helper()

	original := runInstallHook
	t.Cleanup(func() { runInstallHook = original })

	var calls int
	runInstallHook = func() error {
		calls++
		return err
	}

	return &calls
}

// useTempDirs points AppDir and BackupDir at a scratch tree, so the test never
// touches the real /kvmapp.
func useTempDirs(t *testing.T) string {
	t.Helper()

	originalApp, originalBackup := AppDir, BackupDir
	t.Cleanup(func() { AppDir, BackupDir = originalApp, originalBackup })

	root := t.TempDir()
	AppDir = filepath.Join(root, "kvmapp")
	BackupDir = filepath.Join(root, "old")
	if err := os.MkdirAll(AppDir, 0o755); err != nil {
		t.Fatalf("failed to create AppDir: %s", err)
	}

	source := filepath.Join(root, "source")
	if err := os.MkdirAll(source, 0o755); err != nil {
		t.Fatalf("failed to create source: %s", err)
	}
	if err := os.WriteFile(filepath.Join(source, "marker"), []byte("new"), 0o644); err != nil {
		t.Fatalf("failed to write marker: %s", err)
	}

	return source
}
```

```go
// runInstallHook is a variable so tests can avoid running a shell script.
var runInstallHook = execInstallHook

// installHookTimeout bounds the hook. It copies a handful of small files, so a
// run that takes a minute is a run that has hung.
const installHookTimeout = 60 * time.Second

// execInstallHook runs the install script the package carries.
//
// The script installs the boot scripts, which a package update otherwise cannot
// touch: nothing else copies kvmapp/system/init.d into /etc/init.d.
//
// An upstream image carries no such script. There is nothing to install and
// nothing to lose, so its absence is not an error.
func execInstallHook() error {
	path := filepath.Join(AppDir, "system", "install.sh")

	info, err := os.Stat(path)
	if err != nil {
		if errors.Is(err, os.ErrNotExist) {
			return nil
		}
		return err
	}
	if info.Mode()&0o111 == 0 {
		return fmt.Errorf("%s is not executable", path)
	}

	ctx, cancel := context.WithTimeout(context.Background(), installHookTimeout)
	defer cancel()

	output, err := exec.CommandContext(ctx, path).CombinedOutput()
	if err != nil {
		return fmt.Errorf("%w: %s", err, strings.TrimSpace(string(output)))
	}

	log.Infof("install hook: %s", strings.TrimSpace(string(output)))
	return nil
}
```

Then add the call at the end of `installPreparedPackage`, after the `ChmodRecursively` block:

```go
	if err := runInstallHook(); err != nil {
		log.Errorf("install hook failed: %s", err)
```

### Task 4: `install.sh`, the script that installs boot scripts

**Files:**
- Create: `kvmapp/system/install.sh` (mode 755)
- Create: `tools/release/test-install-sh.sh`

**Interfaces:**
- Consumes: Task 3 runs this file at `$AppDir/system/install.sh`.
- Produces: a backup directory at `/root/.ironkvm/initd-backup` holding replaced scripts and a `manifest` file. Each manifest line is `<name> <yes|no>`, where the second field records whether the script existed before this update. Task 5 reads exactly this format.

**Why the backup lives in the root filesystem.** It has to be readable by `S00awatchdog`, which runs before `S01fs` mounts `/data`. The root filesystem is already writable at that point: the watchdog writes `/watchdog.log` there on every boot. Putting it in the root filesystem also makes it per-slot for free, which `/boot` would not: `/boot` is shared, so slot A's backup would be restored into slot B.

Create `kvmapp/system/install.sh`:

```sh
#!/bin/sh
#
# Install the boot scripts an update package carries.
#
# A package update replaces /kvmapp and nothing else. The fork's boot behaviour
# lives in /etc/init.d: the watchdog, the filesystem mounts, the identity
# carry-over, the USB gadget. Without this script a release ships that behaviour
# in the SD image and omits it from the tarball, and the two drift apart with
# nothing to show it.
#
# The updater runs this after unpacking and before restarting the service.
#
# Every replaced script is kept, with a manifest recording whether it existed at
# all, because a script that is new has to be DELETED to undo this, not
# restored. S00awatchdog reads that manifest and undoes the whole set if the
# board fails to come up three times.
#
# The backup lives in the root filesystem rather than on /boot for two reasons.
# S00awatchdog runs before S01fs mounts anything, and the root filesystem is
# already writable there: the watchdog writes its own log to it on every boot.
# And the root filesystem is per-slot, while /boot is shared, so a backup on
# /boot taken from slot A could be restored into slot B.
#
# Environment, for tests:
#   INSTALL_SRC     scripts to install    (default /kvmapp/system/init.d)
#   INSTALL_DEST    where they go         (default /etc/init.d)
#   INSTALL_BACKUP  where originals go    (default /root/.ironkvm/initd-backup)

SRC=${INSTALL_SRC:-/kvmapp/system/init.d}
DEST=${INSTALL_DEST:-/etc/init.d}
BACKUP=${INSTALL_BACKUP:-/root/.ironkvm/initd-backup}

[ -d "$SRC" ] || { echo "install.sh: $SRC is missing, nothing to install"; exit 0; }

# Check every script before installing any of them. A partial install is the
# worst outcome available: some scripts new, some old, and a board that may not
# come up to be repaired. `sh -n` catches the fault that actually happens, which
# is a truncated or mis-edited file.
for f in "$SRC"/*; do
    [ -f "$f" ] || continue
    if ! sh -n "$f" 2>/dev/null; then
        echo "install.sh: ${f##*/} fails a syntax check, installing nothing"
        exit 1
    fi
done

mkdir -p "$BACKUP" "$DEST" || exit 1
: > "$BACKUP/manifest.new"

install_one() {
    name=${1##*/}

    # An identical script is not a change. Copying it anyway would record a
    # rollback to the file it just replaced.
    if [ -f "$DEST/$name" ] && cmp -s "$1" "$DEST/$name"; then
        return 0
    fi

    if [ -e "$DEST/$name" ]; then
        cp "$DEST/$name" "$BACKUP/$name" || return 1
        echo "$name yes" >> "$BACKUP/manifest.new"
    else
        echo "$name no" >> "$BACKUP/manifest.new"
    fi

    cp "$1" "$DEST/$name" || return 1
    chmod 755 "$DEST/$name" || return 1
    echo "install.sh: installed $name"
}

# The watchdog is what repairs the board, so it goes last. If this run dies
# partway, the copy still in place is the one that already works.
for f in "$SRC"/*; do
    [ -f "$f" ] || continue
    [ "${f##*/}" = S00awatchdog ] && continue
    install_one "$f" || exit 1
done

if [ -f "$SRC/S00awatchdog" ]; then
    install_one "$SRC/S00awatchdog" || exit 1
fi

# Only replace the manifest when this run changed something. The updater may
# retry, and a second run finds every script identical, so an unconditional move
# would leave an empty manifest and no way back from the first run.
if [ -s "$BACKUP/manifest.new" ]; then
    mv "$BACKUP/manifest.new" "$BACKUP/manifest"
else
    rm -f "$BACKUP/manifest.new"
fi

sync
exit 0
```

Add the block after the `--- end trial boot ---` marker:

```sh
# --- initd rollback ---
# Undo a package update that installed boot scripts the board cannot boot.
#
# A slot switch is protected by the initramfs and by the trial machinery above.
# A package update is not: it lands in place on the running slot, so there is no
# trial to disarm and no previous slot to fall back to. The counter below is the
# substitute. It is bumped before anything else in the rc sequence runs, and it
# is cleared the moment the board proves it is reachable.
#
# Three, not two: a single slow boot that misses the deadline is common enough,
# and undoing a good update because a switch was still learning would be worse
# than waiting one more boot.
bump_attempts() {
    n=0
    [ -f "$ATTEMPTS" ] && n=$(cat "$ATTEMPTS" 2>/dev/null)
    # A power cut during the write leaves whatever the card had. Treat anything
    # that is not a number as a fresh start rather than refusing to count.
    case "$n" in
        ''|*[!0-9]*) n=0 ;;
    esac
    n=$((n + 1))
    mkdir -p "$IRONDIR" 2>/dev/null
    echo "$n" > "$ATTEMPTS"
    sync
    echo "$n"
}

clear_attempts() {
    rm -f "$ATTEMPTS"
    sync
}

# Returns non-zero when it restored nothing, so the caller cannot report a
# repair that did not happen.
restore_initd() {
    manifest="$INITD_BACKUP/manifest"
    [ -f "$manifest" ] || return 1

    restored=0
    while read -r name existed; do
        [ -n "$name" ] || continue
        # The manifest is written by install.sh, but it lives on a filesystem a
        # power cut can scramble, and this runs as root before anything else.
        case "$name" in
            */*|..*) continue ;;
        esac

        if [ "$existed" = yes ]; then
            [ -f "$INITD_BACKUP/$name" ] || continue
            cp "$INITD_BACKUP/$name" "$INITD/$name" || continue
            chmod 755 "$INITD/$name"
        else
            # The update added this script. Undoing means removing it: there is
            # no original to put back, and leaving it is leaving the fault.
            rm -f "$INITD/$name"
        fi
        restored=$((restored + 1))
    done < "$manifest"

    [ "$restored" -gt 0 ] || return 1

    # Spend the manifest. Without this, every later boot would undo whatever
    # update came after the repair, and the board could never move forward.
    mv "$manifest" "$manifest.done"
    sync
    return 0
}
# --- end initd rollback ---
```

### Task 8: Assemble a whole-card image

**Files:**
- Create: `tools/abslots/build-card.sh`, `tools/abslots/test-build-card.sh`

**Interfaces:**
- Consumes: `tools/abslots/partition.sfdisk`, a boot image from `tools/abslots/repack-boot.sh`, and two ext4 images from `tools/abslots/build-image.sh`.
- Produces: `build-card.sh <boot.sd> <root.img> <recovery.img> <out.img>`, a flashable card image. Task 9 calls it.

**Why this task exists.** `build-image.sh` builds **one ext4 root filesystem**, and it takes five positional arguments:
`build-image.sh <base.tar.zst> <manifest> <payload-dir> <size-mib> <out.img>`. Nothing in the repository assembles those into a card. The existing slots were written to a card that had already been partitioned by hand. A release whose install instruction is "flash this" needs the missing piece.

**The geometry is already decided** by `tools/abslots/partition.sfdisk`, and it is not negotiable in this task:

| Partition | Sectors | Size | Holds |
| --- | --- | --- | --- |
| p1 | 1 to 32768 | 16 MiB | FAT16 `/boot`. The boot ROM finds `fip.bin` by reading the first FAT partition, so this entry must not move. |
| p2 | 40960 to 4235263 | 2 GiB | root A |
| p3 | 4235264 to 8429567 | 2 GiB | root B |
| p5 | 8437760 to 10534911 | 1 GiB | recovery |
| p6 | 10543104 to 60506111 | 23.82 GiB | exfat `/data` |

**Two decisions this task makes.**

The image is **truncated after p5**. The file describes p6 in its partition table but carries no bytes for it, so the image is 5.02 GiB rather than 28.85 GiB. `S01fs` already formats the data device when its marker is present, so p6 is created on first boot. Compressing 28.85 GiB of mostly zeros would cost minutes on every release for nothing.

**Slot B ships empty.** The image populates p2 and p5 only. B is what the first update writes, and populating it would add 2 GiB to the image to ship a second copy of the same thing.

**The size limit is stated, not solved.** The table is for a card of at least 60506112 sectors, which is a 32 GB class card. A larger card leaves the extra space unused. Growing p6 on first boot is a later release, and it goes in `CHANGELOG.md` under `Known limits`.

Create `tools/abslots/build-card.sh`:

```sh
#!/bin/sh
# Assemble a flashable card image from a boot image and two root images.
#
#   build-card.sh <boot.sd> <root.img> <recovery.img> <out.img>
#
# Needs sfdisk, mkfs.vfat and e2fsck. Nothing here runs on the device.
#
# build-image.sh produces one ext4 root filesystem. This puts those filesystems
# where the boot ROM and the initramfs expect to find them. Before this existed,
# a card had to be partitioned by hand, which is not an install instruction that
# can be published.
#
# The image is truncated after the recovery partition. Its table still describes
# the data partition, and S01fs formats that device on first boot when its
# marker is present, so carrying 23.82 GiB of zeros would cost minutes of
# compression on every release for nothing.
#
# Slot B is left empty. It is what the first update writes, and populating it
# would add 2 GiB to every download to ship a second copy of slot A.
#
# Environment, for tests:
#   CARD_TABLE            the sfdisk layout      (default partition.sfdisk)
#   CARD_TRUNCATE_AFTER   partition to end after (default 5)
set -eu

HERE=$(cd "$(dirname "$0")" && pwd)
BOOT=${1:?usage: build-card.sh <boot.sd> <root.img> <recovery.img> <out.img>}
ROOT=${2:?usage: build-card.sh <boot.sd> <root.img> <recovery.img> <out.img>}
RECOVERY=${3:?usage: build-card.sh <boot.sd> <root.img> <recovery.img> <out.img>}
OUT=${4:?usage: build-card.sh <boot.sd> <root.img> <recovery.img> <out.img>}

TABLE=${CARD_TABLE:-$HERE/partition.sfdisk}
TRUNCATE_AFTER=${CARD_TRUNCATE_AFTER:-5}

for f in "$BOOT" "$ROOT" "$RECOVERY" "$TABLE"; do
    [ -f "$f" ] || { echo "no such file: $f" >&2; exit 1; }
done

# field <partition> <key> reads the layout rather than repeating it. Two copies
# of a geometry drift, and the copy that drifts is the one nobody runs.
field() {
    sed -n "s/^$1 *: *.*$2=\([0-9]*\).*/\1/p" "$TABLE" | head -1
}

P1_START=$(field 1 start); P1_SIZE=$(field 1 size)
P2_START=$(field 2 start); P2_SIZE=$(field 2 size)
P5_START=$(field 5 start); P5_SIZE=$(field 5 size)
END_START=$(field "$TRUNCATE_AFTER" start)
END_SIZE=$(field "$TRUNCATE_AFTER" size)
TOTAL=$((END_START + END_SIZE))

# Refuse an oversized filesystem before writing anything. dd would otherwise
# write it straight over the next partition, and the fault would first appear as
# a slot that fails e2fsck on the device.
fits() {
    have=$(( $(wc -c < "$1") / 512 ))
    [ "$have" -le "$2" ] && return 0
    echo "$1 is $have sectors, partition holds $2" >&2
    return 1
}
fits "$ROOT" "$P2_SIZE" || exit 1
fits "$RECOVERY" "$P5_SIZE" || exit 1

WORK="$OUT.partial"
rm -f "$WORK"
truncate -s $((TOTAL * 512)) "$WORK"

sfdisk --no-reread --no-tell-kernel "$WORK" < "$TABLE" > /dev/null

# p1 is FAT and carries the boot image. It is the one partition the boot ROM
# reads directly, so it is written rather than formatted from a template.
mkfs.vfat -F 16 -n BOOT --offset "$P1_START" "$WORK" "$((P1_SIZE / 2))" > /dev/null
dd if="$BOOT" of="$WORK" bs=512 seek="$P1_START" conv=notrunc status=none

dd if="$ROOT"     of="$WORK" bs=512 seek="$P2_START" conv=notrunc status=none
dd if="$RECOVERY" of="$WORK" bs=512 seek="$P5_START" conv=notrunc status=none

# Read the filesystems back out and check them. A copy that lands at the wrong
# offset still produces a plausible file, and the first thing that would notice
# is a board that boots into nothing.
check_fs() {
    tmp=$(mktemp)
    dd if="$WORK" of="$tmp" bs=512 skip="$1" count="$2" status=none
    if ! e2fsck -fn "$tmp" > /dev/null 2>&1; then
        rm -f "$tmp"
        echo "the filesystem at sector $1 does not pass e2fsck" >&2
        return 1
    fi
    rm -f "$tmp"
}
check_fs "$P2_START" "$P2_SIZE" || { rm -f "$WORK"; exit 1; }
check_fs "$P5_START" "$P5_SIZE" || { rm -f "$WORK"; exit 1; }

mv "$WORK" "$OUT"
echo "built $OUT ($((TOTAL / 2048)) MiB, slot B empty, data partition formatted on first boot)"
```

```sh
#   STOCK_BOOT_SD    the stock boot.sd to repack        (default base/boot.sd)

# verify checks that the manifest describes the artifact it names. This
# repository has already lost three guards to rot; a release script that cannot
# check its own output would publish a feed pointing at a package that does not
# match it, and nothing would notice until a device tried to install.
verify() {
    [ -f "$OUT/$PKG" ]          || { echo "missing $OUT/$PKG" >&2; return 1; }
    [ -f "$OUT/latest.json" ]   || { echo "missing $OUT/latest.json" >&2; return 1; }

    actual=$(openssl dgst -sha512 -binary "$OUT/$PKG" | openssl base64 -A)
    stated=$(sed -n 's/.*"sha512"[[:space:]]*:[[:space:]]*"\([^"]*\)".*/\1/p' "$OUT/latest.json")
    [ "$actual" = "$stated" ] || { echo "sha512 in latest.json does not match $PKG" >&2; return 1; }

    named=$(sed -n 's/.*"name"[[:space:]]*:[[:space:]]*"\([^"]*\)".*/\1/p' "$OUT/latest.json")
    [ "$named" = "$PKG" ] || { echo "latest.json names '$named', built '$PKG'" >&2; return 1; }

    size=$(wc -c < "$OUT/$PKG" | tr -d ' ')
    stated_size=$(sed -n 's/.*"size_bytes"[[:space:]]*:[[:space:]]*\([0-9]*\).*/\1/p' "$OUT/latest.json")
    [ "$size" = "$stated_size" ] || { echo "size_bytes does not match $PKG" >&2; return 1; }

    # update.go derives the expected root from the package name, so a tarball
    # whose top directory disagrees unpacks into nothing the updater will accept.
    root=$(tar tzf "$OUT/$PKG" 2>/dev/null | head -1 | cut -d/ -f1)
    [ "$root" = "ironkvm_${VERSION}" ] || {
        echo "tarball top directory is '$root', expected ironkvm_${VERSION}" >&2; return 1; }

    echo "verify: latest.json and $PKG agree"
}

if [ "$VERIFY_ONLY" = "1" ]; then

    exit $?
fi

echo "==> assembling the package"

echo "$VERSION" > "$STAGE/ironkvm_${VERSION}/version"

# The base version travels beside the version because semver cannot carry it.
BASE=$(cat "${BASE_VERSION_FILE:-base/version}" 2>/dev/null || echo "unknown")
echo "$BASE" > "$STAGE/ironkvm_${VERSION}/base-version"

chmod 755 "$STAGE/ironkvm_${VERSION}/system/install.sh"
tar czf "$OUT/$PKG" -C "$STAGE" "ironkvm_${VERSION}"

echo "==> building the slot filesystems"
# build-image.sh takes five positional arguments and produces ONE ext4 root:
#   <base.tar.zst> <manifest> <payload-dir> <size-mib> <out.img>
# The sizes are the partition sizes from partition.sfdisk: 2048 MiB for a root,
# 1024 MiB for recovery.
tools/abslots/build-image.sh "$BASE_TAR" tools/abslots/manifest/root.manifest \
    "$STAGE/ironkvm_${VERSION}" 2048 "$STAGE/root.img"
tools/abslots/build-image.sh "$BASE_TAR" tools/abslots/manifest/recovery.manifest \
    "$STAGE/ironkvm_${VERSION}" 1024 "$STAGE/recovery.img"

echo "==> repacking the boot image"
tools/abslots/repack-boot.sh "$STOCK_BOOT_SD" "$STAGE/boot"

echo "==> assembling the card"
tools/abslots/build-card.sh "$STAGE/boot/boot.sd" "$STAGE/root.img" \
    "$STAGE/recovery.img" "$OUT/ironkvm-${VERSION}-sdcard.img"
xz -T0 -f "$OUT/ironkvm-${VERSION}-sdcard.img"

echo "==> writing latest.json"
SHA=$(openssl dgst -sha512 -binary "$OUT/$PKG" | openssl base64 -A)
SIZE=$(wc -c < "$OUT/$PKG" | tr -d ' ')
UNPACKED=$(tar tzvf "$OUT/$PKG" | awk '{ total += $3 } END { print total }')
cat > "$OUT/latest.json" <<EOF
{
  "manifest_version": 2,
  "version": "$VERSION",
  "name": "$PKG",
  "url": "https://github.com/$REPO/releases/download/v$VERSION/$PKG",
  "sha512": "$SHA",
  "size": $SIZE,
  "size_bytes": $SIZE,
  "unpacked_size_bytes": $UNPACKED
}
EOF

echo "==> checksums"
( cd "$OUT" && sha256sum "$PKG" "$IMG" > SHA256SUMS )
minisign -Sm "$OUT/SHA256SUMS"

verify

publish() {
    if [ "$DRY_RUN" = "1" ]; then
        echo "dry run: nothing published. Artifacts are in $OUT"
        return 0
    fi

    git tag -a "v$VERSION" -m "IronKVM $VERSION"
    git push origin "v$VERSION"
    gh release create "v$VERSION" --repo "$REPO" --title "IronKVM $VERSION" \
        --notes-file "$OUT/notes.md" \
        "$OUT/$PKG" "$OUT/$IMG" "$OUT/SHA256SUMS" "$OUT/SHA256SUMS.minisig"

    # The feed is a separate branch so the package never enters the repository.
    git worktree add "$STAGE/pages" gh-pages
    cp "$OUT/latest.json" "$STAGE/pages/latest.json"
    ( cd "$STAGE/pages" && git add latest.json \
      && git commit -m "Publish IronKVM $VERSION" && git push origin gh-pages )
    git worktree remove "$STAGE/pages"
}

publish
echo "IronKVM $VERSION done"
```

### Task 11: Prove the rollback on hardware

**Files:**
- Create: `tools/release/acceptance-initd-rollback.sh`

**Interfaces:**
- Consumes: Tasks 4 and 5.
- Produces: a recorded pass or fail. This is the task that decides whether the mechanism is delivered.

**Do not run this unattended.** It deliberately breaks the running board. The board must be reachable another way first: confirm the recovery slot works and that the ACM console on the managed host answers, because a fault that blocks `rcS` takes ssh with it and there is no remote power cycle.

- [ ] **Step 1: Write the harness**

Create `tools/release/acceptance-initd-rollback.sh`, which takes the device address and does this:

1. Record the current `/etc/init.d/S01fs` checksum and the output of `slot status`.
2. Build a package whose `system/init.d/S01fs` is syntactically valid but exits 1 before mounting anything, and whose version is one patch above the installed one.
3. Serve it, point the device's update server at it, and run the update through the API.
4. Reboot, then poll for the board.
5. Assert that the board returns, that the third boot restored the original `S01fs`, that `/root/.ironkvm/initd-backup/manifest.done` exists, and that `/watchdog.log` carries the line `restored the previous /etc/init.d`.
6. Restore the update server setting.

Note in the script's header that a syntactically valid script is used on purpose: `install.sh` refuses one that fails `sh -n`, so a syntax error would test the wrong guard.

- [ ] **Step 2: Confirm the escape routes before breaking anything**

```shell
ssh root@<device> 'slot status && ls -la /boot/recovery 2>/dev/null; echo "---"; cat /watchdog.log | tail -5'
```

Expected: a slot report, and a watchdog log ending in `standing down`.

- [ ] **Step 3: Run it**

```shell
sh tools/release/acceptance-initd-rollback.sh root@<device>
```

Expected: the board goes away, misses two boots, and returns on the third with the original `S01fs` in place.

- [ ] **Step 4: Record the result**

Write the outcome, the timings, and anything surprising into `tools/release/README.md` under a heading `Acceptance record`. A test that ran once and was never written down is a test nobody can trust later.

Boot-success rollback: Task 5. Documentation and the diff: Task 10. Testing strategy: folded into each task, with the hardware proof as Task 11. Deferred items (slot-aware updates, preview channel, OLED and access point strings, growing p6 on a larger card) appear in Task 10's `Known limits` and `What still says NanoKVM`, so they are recorded rather than forgotten.

**One spec correction.** The spec left open where the boot-attempt counter lives and said it must be verified on hardware. Reading `S00awatchdog` settled it without hardware: the script already writes `/watchdog.log` to the root filesystem at that point in boot, and it already carries `ensure_boot_mounted` for the case where `/boot` is not mounted. The root filesystem is therefore known writable, and it is per-slot, which `/boot` is not. A backup on the shared `/boot` taken from slot A could be restored into slot B. Tasks 4 and 5 use `/root/.ironkvm/` and say why.

**One gap the spec did not see.** The spec lists a full A/B/recovery card image as a release artifact, and no such builder exists. `build-image.sh` produces one ext4 root filesystem from five positional arguments, and the slots in use were written to a card that had already been partitioned by hand. Task 8 was added to close that, and it makes two decisions the spec did not cover: the image is truncated after the recovery partition, because `S01fs` formats the data device on first boot; and slot B ships empty, because it is what the first update writes. The card size limit that follows from a fixed partition table is stated in the documentation rather than solved.

**Placeholder scan.** No `TBD`, no `TODO`, no "add error handling". Task 9 asks for prose to be written by hand rather than supplying it, which is correct: the change list is a judgement about 254 commits, not a code block, and generating it mechanically is the failure mode the task warns against.

**Type consistency.** `runInstallHook` and `execInstallHook` are used consistently in Task 3. The manifest format `<name> <yes|no>` is written by Task 4 and read by Task 5 in that exact shape. `baseVersionFile` and `baseVersion()` match between Task 7's test and its implementation. `StableURL` and `SipeedURL` are named the same in Task 6 and Task 8.
