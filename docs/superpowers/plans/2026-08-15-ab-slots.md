# A/B/recovery slots Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replace the loop-image slot scheme with two real root partitions and a recovery root, so a slot that boots and starts no listener returns the board by itself instead of needing the SD card in a reader.

**Architecture:** The initramfs selects the root from markers on the FAT partition. A slot on trial is named by `/boot/slot.try`, which the initramfs deletes before it hands over, so the suspect never votes on its own trial. The slot confirms itself once it is reachable. Images are built from a pinned base plus a manifest, never cloned from a running board.

**Tech Stack:** busybox `ash`, `sfdisk`, `mke2fs -d`, `e2fsck`, `dumpimage`/`mkimage` (u-boot-tools), `cpio`, Docker for the test container.

**Spec:** `docs/superpowers/specs/2026-08-15-ab-slots-design.md`

## Global Constraints

- Target shell is busybox `ash` on the device. No bashisms in anything under `tools/abslots/device/` or in any `/etc/init.d` script.
- Every file that reaches the device is LF only and mode 755 if it is a script. `.gitattributes` covers the repository; `tools/test-line-endings.sh` is the check.
- No em dashes in any file, commit message, or document.
- Partition 1 keeps start sector 1, size 32768, type `c`, and the boot flag. It is never reformatted. The boot ROM finds `fip.bin` by reading it.
- The exact partition table is fixed and given in Task 8. Do not recompute it.
- The initramfs `PATH` is `/` with twelve busybox symlinks. Any other applet must be called as `/busybox <applet>`.
- `repack-boot.sh` must keep passing: kernel and device tree byte-identical, only `/init` differs, `dev/console` char 5,1, twelve symlinks, every command resolvable.
- The card is on the Unraid host `unraid` (10.0.0.30) as `/dev/sdg`, mounted read-only at `/tmp/kvmroot` (p2), `/tmp/kvmslot` (slot143 image) and `/tmp/kvmdata` (p3).
- A full card backup exists at `unraid:/mnt/disk1/nanokvm-card-20260815.img.zst`. Do not write to `/dev/sdg` before Task 1 confirms it.
- The base is the latest **official** release, not a clone of this board. Two artifacts, both from `github.com/sipeed/NanoKVM/releases`:

| layer | tag | file | size |
| --- | --- | --- | --- |
| system image | `v1.4.3`, 2026-06-10 | `20260610_NanoKVM_Rev1_4_3.img` | 1627390464 |
| application | `2.5.0`, 2026-08-04 | `nanokvm_2.5.0.tar.gz` with `sha256.txt` | 16464014 |

- `v1.4.3` is the newest system image. The card's `/boot/ver` reads `2026-06-10-1_4_3.img`, but slot A carries Feb 2025 file dates and has no `/etc/ipmi`, which v1.4.3 ships. Measured, the base is a genuine upgrade rather than a re-fetch.
- Do **not** take the application from `https://cdn.sipeed.com/nanokvm/latest.zip`. That stable channel still serves 2.4.3, and the board already runs 2.5.0, so building from it would be a downgrade. The GitHub release is the source.
- A built image is therefore three declared layers: the official rootfs, the official application, and the fork delta. Nothing is copied from a running board.

- [ ] **Step 1: Write the failing test**

Create `tools/abslots/test-partition.sh`:

```sh
#!/bin/sh
# Check the partition table before it is ever applied to a card.
#
#   test-partition.sh [path-to-partition.sfdisk]
#
# The table is applied once, to the only card. p1 holds fip.bin and boot.sd and
# the boot ROM finds it by reading the first FAT partition, so an entry that
# moves p1, resizes it, changes its type or drops its boot flag makes the board
# unbootable by every recovery in this design. That is the case this file
# exists for; the rest is arithmetic.
TABLE=${1:-$(dirname "$0")/partition.sfdisk}
[ -f "$TABLE" ] || { echo "usage: test-partition.sh <partition.sfdisk>"; exit 1; }

WORK=$(mktemp -d)
trap 'rm -rf "$WORK"' EXIT

fails=0
note() { printf '  %-62s %s\n' "$1" "$2"; [ "$2" = FAIL ] && fails=$((fails + 1)); return 0; }

DISK_SECTORS=60506112

echo "===== the table applies to a disk of the card's size ====="

truncate -s $((DISK_SECTORS * 512)) "$WORK/disk.img"
if sfdisk --no-reread --no-tell-kernel "$WORK/disk.img" < "$TABLE" > "$WORK/apply.log" 2>&1; then
    note "sfdisk accepts the table" OK
else
    note "sfdisk accepts the table" FAIL
    sed 's/^/    /' "$WORK/apply.log" | tail -10
    echo
    echo "$fails case(s) FAILED"
    exit "$fails"
fi

sfdisk -d "$WORK/disk.img" > "$WORK/back" 2>/dev/null
field() { awk -v p="$1" -v k="$2" '$1 ~ p"$" { for (i = 1; i <= NF; i++) if ($i == k"=") print $(i+1) }' "$WORK/back" | tr -d ','; }

# p1 is the only entry with a fixed expected value, because it must not change.
[ "$(field 1 start)" = 1 ]     && note "p1 starts at sector 1" OK     || note "p1 starts at sector $(field 1 start), want 1" FAIL
[ "$(field 1 size)" = 32768 ]  && note "p1 is 32768 sectors" OK       || note "p1 is $(field 1 size) sectors, want 32768" FAIL
grep -q '^.*1 :.*type=c' "$WORK/back"        && note "p1 keeps type c" OK        || note "p1 keeps type c" FAIL
grep -q '^.*1 :.*bootable' "$WORK/back"      && note "p1 keeps the boot flag" OK || note "p1 keeps the boot flag" FAIL

echo
echo "===== the roots are equal and aligned ====="

[ "$(field 2 size)" = "$(field 3 size)" ] \
    && note "root A and root B are the same size" OK \
    || note "root A is $(field 2 size), root B is $(field 3 size)" FAIL

[ "$(field 2 size)" = 4194304 ] && note "each root is 2.00 GiB" OK || note "each root is $(field 2 size) sectors" FAIL
[ "$(field 5 size)" = 2097152 ] && note "recovery is 1.00 GiB" OK  || note "recovery is $(field 5 size) sectors" FAIL

for p in 2 3 5 6; do
    s=$(field "$p" start)
    [ $((s % 8192)) -eq 0 ] \
        && note "p$p starts on a 4 MiB boundary" OK \
        || note "p$p starts at $s, not a 4 MiB boundary" FAIL
done

echo
echo "===== nothing overlaps and nothing runs off the end ====="

last=$(( $(field 6 start) + $(field 6 size) ))
[ "$last" -le "$DISK_SECTORS" ] \
    && note "the last partition ends within the disk" OK \
    || note "the last partition ends at $last, disk is $DISK_SECTORS" FAIL

overlap=$(awk '/^\/.*start=/ {
    for (i = 1; i <= NF; i++) { if ($i == "start=") s = $(i+1) + 0; if ($i == "size=") n = $(i+1) + 0 }
    if ($0 ~ /type=5/) next
    print s, s + n - 1
}' "$WORK/back" | sort -n | awk 'NR > 1 && $1 <= prev { print "overlap" } { prev = $2 }')
[ -z "$overlap" ] && note "no two data partitions overlap" OK || note "partitions overlap" FAIL

echo
if [ "$fails" -eq 0 ]; then echo "all cases passed"; else echo "$fails case(s) FAILED"; fi
exit "$fails"
```

```
# NanoKVM A/B/recovery layout for the 60506112 sector (28.85 GiB) card.
#
# p1 is copied from the card as it is. Start sector 1, 32768 sectors, type c,
# bootable. The boot ROM finds fip.bin by reading the first FAT partition, so
# this entry is the one thing here that must not change. It is not reformatted.
#
# Everything from p2 is 4 MiB aligned, which is the erase block size that
# matters on this card. p1 cannot be aligned because it cannot move.
#
# p4 is the extended container. Logical partitions each cost one EBR sector, so
# p5 and p6 start 8192 sectors after the preceding boundary rather than
# immediately, which keeps them aligned as well.
label: dos
label-id: 0x70781617
unit: sectors

1 : start=1,        size=32768,    type=c, bootable
2 : start=40960,    size=4194304,  type=83
3 : start=4235264,  size=4194304,  type=83
4 : start=8429568,  size=52076544, type=5
5 : start=8437760,  size=2097152,  type=83
6 : start=10543104, size=49963008, type=7
```

## Task 4: Discover the manifest by diffing the slot against the base

**Files:**
- Create: `tools/abslots/manifest/root.manifest`
- Create: `tools/abslots/manifest/recovery.manifest`

**Interfaces:**
- Consumes: `BASE_TAR` from Task 2.
- Produces: two manifests read by `build-image.sh` in Task 5.

The manifest format is three verbs, one per line, `#` for comments:

```
add     <path in the payload tree>   <path in the image>
remove  <path in the image>
touch   <path in the image>
```

`set` is not a verb. Device names are written into `/etc/nanokvm-slots.conf` by the builder itself, so there is exactly one place they exist.

- [ ] **Step 1: Produce the difference**

```bash
ssh unraid 'mkdir -p /tmp/ob && zstd -dc /mnt/disk1/nanokvm-base-official.tar.zst | tar -xf - -C /tmp/ob
cd /tmp/ob    && find . -xdev -type f -print | sort > /tmp/base.list
cd /tmp/kvmslot && find . -xdev \( -path ./root -o -path ./kvmapp \) -prune -o -type f -print | sort > /tmp/slot.list
echo "=== only in the fork slot, so candidates for add ==="; comm -13 /tmp/base.list /tmp/slot.list | head -60
echo "=== only in the official base, so candidates for remove ==="; comm -23 /tmp/base.list /tmp/slot.list | head -40'
```

`/kvmapp` and `/root` are pruned from the slot side on purpose. `/kvmapp` comes from the official 2.5.0 tarball plus the fork's own copy, so it is not discovered here, and `/root` is accumulated operator state that must never reach an image.

`official-kvmapp/` is build input, not source. Add it to `.gitignore` rather than committing 16MB of a published tarball into the fork.

- [ ] **Step 3: Write the root manifest**

Create `tools/abslots/manifest/root.manifest`. Start from the difference above and keep the payload paths repository-relative. This is the manifest as of 2026-08-15; adjust only if Step 1 reports a file this list does not cover.

```
# The full NanoKVM root: the base plus everything this fork adds.
#
# Paths on the left are relative to the payload tree the builder is given.
# Paths on the right are absolute inside the image.

# The install package, in two layers and in this order.
#
# First the official 2.5.0 release, unpacked by Task 4 step 2 into
# payload/official-kvmapp/. /kvmapp is a directory inside the root rather than a
# partition, so each slot carries its own copy and its own server binary.
#
# Then the fork's own kvmapp on top. The order is what makes the image
# describable: everything in the first layer is published and checksummed by
# Sipeed, and everything the fork changes is the second layer and nothing else.
add     official-kvmapp/                          /kvmapp/
add     kvmapp/                                   /kvmapp/

# The stripped server build. 17209304 bytes against 24279504, because the
# binary runs from tmpfs and every debug byte is pinned RAM.
add     server/NanoKVM-Server                     /kvmapp/server/NanoKVM-Server

# Init scripts the fork adds or replaces. S95nanokvm is replaced; the rest do
# not exist in the base.
```

Create `tools/abslots/build-image.sh`:

```sh
#!/bin/sh
# Build one ext4 root image from a pinned base plus a manifest.
#
#   build-image.sh <base.tar.zst> <manifest> <payload-dir> <size-mib> <out.img>
#
# Needs mke2fs, e2fsck, tar and zstd. Run it in a container or on the Unraid
# host; nothing here runs on the device.
#
# mke2fs -d populates the image from a directory with no loop mount and no
# privileged mount, which is what makes this buildable through Docker on
# Windows at all.
#
# Byte reproducibility is not promised: ext4 records timestamps. Content
# reproducibility is, and test-build-image.sh is how it is checked.
set -e

BASE=${1:?usage: build-image.sh <base.tar.zst> <manifest> <payload-dir> <size-mib> <out.img>}
MANIFEST=${2:?usage: build-image.sh <base.tar.zst> <manifest> <payload-dir> <size-mib> <out.img>}
PAYLOAD=${3:?usage: build-image.sh <base.tar.zst> <manifest> <payload-dir> <size-mib> <out.img>}
SIZE_MIB=${4:?usage: build-image.sh <base.tar.zst> <manifest> <payload-dir> <size-mib> <out.img>}
OUT=${5:?usage: build-image.sh <base.tar.zst> <manifest> <payload-dir> <size-mib> <out.img>}

STAGE=$(mktemp -d)
trap 'rm -rf "$STAGE"' EXIT

echo "############ 1. unpack the base"
mkdir -p "$STAGE/tree"
zstd -dc "$BASE" | tar --numeric-owner -xf - -C "$STAGE/tree"
printf '  %-40s %s files\n' "base" "$(find "$STAGE/tree" -type f | wc -l)"

echo
echo "############ 2. apply the manifest"
# Order matters: remove before add, so a manifest can replace a directory by
# removing it and adding a new one. touch runs last because a touched marker
# may live inside a directory that add created.
grep -v '^[[:space:]]*#' "$MANIFEST" | grep -v '^[[:space:]]*$' > "$STAGE/m"

while read -r verb a b; do
    [ "$verb" = remove ] || continue
    rm -rf "$STAGE/tree${a}"
    echo "  remove  $a"
done < "$STAGE/m"

while read -r verb a b; do
    [ "$verb" = add ] || continue
    [ -e "$PAYLOAD/$a" ] || { echo "  add     $a -> MISSING in payload"; exit 1; }
    mkdir -p "$(dirname "$STAGE/tree${b}")"
    cp -a "$PAYLOAD/$a" "$STAGE/tree${b}"
    echo "  add     $a -> $b"
done < "$STAGE/m"

while read -r verb a b; do
    [ "$verb" = touch ] || continue
    mkdir -p "$(dirname "$STAGE/tree${a}")"
    : > "$STAGE/tree${a}"
    echo "  touch   $a"
done < "$STAGE/m"

echo
echo "############ 3. record provenance"
{
    echo "base    $(basename "$BASE")"
    echo "basesha $(sha256sum "$BASE" | cut -d' ' -f1)"
    echo "manifest $(basename "$MANIFEST")"
    echo "manifestsha $(sha256sum "$MANIFEST" | cut -d' ' -f1)"
    echo "built   ${SOURCE_DATE_EPOCH:-$(date -u +%Y-%m-%dT%H:%M:%SZ)}"
} > "$STAGE/tree/etc/slot-manifest"
sed 's/^/  /' "$STAGE/tree/etc/slot-manifest"

echo
echo "############ 4. device names, written once"
cat > "$STAGE/tree/etc/nanokvm-slots.conf" <<'CONF'
# Device names for the A/B layout. Read by S01fs and by the slot tool. No
# script computes a device from a partition number: in this layout p3 is a root
# filesystem, and S01fs used to run mkfs.exfat on p3.
SLOT_A=/dev/mmcblk0p2
SLOT_B=/dev/mmcblk0p3
RECOVERY=/dev/mmcblk0p5
DATA_DEV=/dev/mmcblk0p6
CONF

echo
echo "############ 5. gates"
fail=0
note() { printf '  %-58s %s\n' "$1" "$2"; [ "$2" = FAIL ] && fail=1; return 0; }

crlf=$(find "$STAGE/tree/etc/init.d" -type f 2>/dev/null | while read -r f; do
    [ "$(tr -cd '\r' < "$f" | wc -c)" -gt 0 ] && echo "$f"
done | wc -l)
[ "$crlf" -eq 0 ] && note "every init script is LF only" OK || note "$crlf init script(s) carry CR" FAIL

badmode=$(find "$STAGE/tree/etc/init.d" -name 'S*' -type f ! -perm -100 2>/dev/null | wc -l)
[ "$badmode" -eq 0 ] && note "every S* script is executable" OK || note "$badmode S* script(s) are not executable" FAIL

badsyntax=0
for f in "$STAGE/tree"/etc/init.d/*; do
    [ -f "$f" ] || continue
    head -1 "$f" | grep -q '^#!' || continue
    sh -n "$f" 2>/dev/null || badsyntax=$((badsyntax + 1))
done
[ "$badsyntax" -eq 0 ] && note "sh -n accepts every init script" OK || note "$badsyntax script(s) fail sh -n" FAIL

[ -e "$STAGE/tree/etc/kvm.disk0" ] && note "/etc/kvm.disk0 is present" OK || note "/etc/kvm.disk0 is missing, first boot would reformat /data" FAIL
[ -e "$STAGE/tree/etc/kvm/ssh_stop" ] && note "/etc/kvm/ssh_stop is absent" FAIL || note "/etc/kvm/ssh_stop is absent" OK
[ -e "$STAGE/tree/swapfile" ] && note "no /swapfile" FAIL || note "no /swapfile" OK

while read -r verb a b; do
    [ "$verb" = remove ] || continue
    [ -e "$STAGE/tree${a}" ] && note "removed: $a" FAIL || note "removed: $a" OK
done < "$STAGE/m"

if [ "$fail" -ne 0 ]; then
    echo
    echo "gates failed; no image written"
    exit 1
fi

echo
echo "############ 6. build the filesystem"
# The journal stays. This is a root filesystem on a board whose normal way of
# ending is a power cut, and an unclean unmount with no journal is a repair
# with no record of what was in flight. Dropping it would buy smaller, more
# comparable images and cost the property that matters.
#
# metadata_csum_seed is dropped so that the image is not bound to the UUID it
# was built with, which lets the same image be written to either slot.
rm -f "$OUT"
mke2fs -q -t ext4 -L "$(basename "$OUT" .img)" -d "$STAGE/tree" -O ^metadata_csum_seed \
       "$OUT" "${SIZE_MIB}m"
e2fsck -fp "$OUT" >/dev/null 2>&1 || true

echo
printf '  %-40s %s\n' "image" "$OUT"
printf '  %-40s %s bytes\n' "size" "$(wc -c < "$OUT")"
printf '  %-40s %s\n' "sha256" "$(sha256sum "$OUT" | cut -d' ' -f1)"
```

Create `tools/abslots/device/rcS`. A boot that completes with no listeners leaves no evidence otherwise, and `sync` is what makes the log survive a board that is ended with a power cut:

```sh
#!/bin/sh
# Run every /etc/init.d/S* in order, and record each one in /bootlog.
#
# The log is truncated at the start of each boot, so it always describes the
# boot you are looking at. It is synced after every line, because a stalled
# board is usually ended by cutting power, and an unsynced log dies with the
# page cache.
BOOTLOG=/bootlog

: > "$BOOTLOG"
sync

for i in /etc/init.d/S??* ; do
    case "$i" in
        *.sh) continue ;;
    esac
    [ -x "$i" ] || continue

    echo "$(cut -d. -f1 /proc/uptime)s  start  $i" >> "$BOOTLOG"
    sync
    "$i" start
    rc=$?
    echo "$(cut -d. -f1 /proc/uptime)s  done   $i (rc=$rc)" >> "$BOOTLOG"
    sync
done

echo "$(cut -d. -f1 /proc/uptime)s  rcS complete" >> "$BOOTLOG"
sync
```

```sh
#!/bin/sh
# Check the initramfs slot dispatch, in a sandbox.
#
#   test-dispatch.sh [selection.inc] [dispatch.inc]
#
# The dispatch decides which filesystem the board runs before anything can log,
# so every branch is checked here rather than on hardware. The one that matters
# most is the disarm: /boot/slot.try must be deleted BEFORE the trial is handed
# control, because a slot that hangs cannot be relied on to disarm itself.
SEL=${1:-$(dirname "$0")/init-slot-selection.inc}
DIS=${2:-$(dirname "$0")/init-mount-dispatch.inc}
[ -f "$SEL" ] && [ -f "$DIS" ] || { echo "usage: test-dispatch.sh <selection.inc> <dispatch.inc>"; exit 1; }

WORK=$(mktemp -d)
trap 'rm -rf "$WORK"' EXIT

fails=0
note() { printf '  %-62s %s\n' "$1" "$2"; [ "$2" = FAIL ] && fails=$((fails + 1)); return 0; }

# run_case <slot> <try> <mountable-list> ; prints the chosen device
run_case() {
    rm -rf "$WORK/boot"; mkdir -p "$WORK/boot"
    [ -n "$1" ] && printf '%s\n' "$1" > "$WORK/boot/slot"
    [ -n "$2" ] && printf '%s\n' "$2" > "$WORK/boot/slot.try"
    MOUNTABLE="$3"
    export MOUNTABLE
    (
        BOOT="$WORK/boot"
        export BOOT
        # Stubs. mount succeeds only for a device named in MOUNTABLE.
        mount() {
            for d in $MOUNTABLE; do [ "$d" = "$3" ] && return 0; done
            return 1
        }
        e2fsck() { return 0; }
        msc() { echo "DEVICE=msc"; exit 0; }
        slotlog() { :; }
        . "$SEL"
        . "$DIS"
        echo "DEVICE=${bootdev}"
    ) 2>/dev/null
}

echo "===== the dispatch chooses the right root ====="

A=/dev/mmcblk0p2; B=/dev/mmcblk0p3; R=/dev/mmcblk0p5

out=$(run_case "" "" "$A $B $R");         echo "$out" | grep -q "DEVICE=$A" && note "no markers boots slot A" OK || note "no markers boots slot A ($out)" FAIL
out=$(run_case "b" "" "$A $B $R");        echo "$out" | grep -q "DEVICE=$B" && note "slot=b boots slot B" OK || note "slot=b boots slot B ($out)" FAIL
out=$(run_case "b" "a" "$A $B $R");       echo "$out" | grep -q "DEVICE=$A" && note "a trial overrides the trusted slot" OK || note "a trial overrides the trusted slot ($out)" FAIL
```

```sh
# --- slot selection ---
# Runs while /boot is still mounted, because the dispatch below does not have
# it. Three markers are read here and one is deleted here.
#
#   /boot/slot        the trusted slot: a, b, or absent meaning a
#   /boot/slot.try    a slot on trial, written by the operator
#   /boot/recovery    if present, boot recovery and nothing else
#
# The delete is the whole design. A slot on trial is disarmed BEFORE it is
# handed control, so a hang, a panic, an oops, a power cut and a slot that
# starts no listener all reach the same next boot, which is the trusted slot.
# The suspect never votes on its own trial.
BOOT=${BOOT:-/boot}

trusted=a
if [ -e "$BOOT/slot" ]
then
	read trusted < "$BOOT/slot"
fi
if [ -z "${trusted}" ]
then
	trusted=a
fi

trial=
if [ -e "$BOOT/slot.try" ]
then
	read trial < "$BOOT/slot.try"

	/busybox rm -f "$BOOT/slot.try"
	/busybox sync

	# Deleting on FAT is a directory entry write. If it did not land and the
	# trial hangs on every boot, the board loops for ever, which is worse than
	# the dead board this exists to prevent. Proof of disarm before the trial is
	# honoured turns that loop into one wasted boot.
	if [ -e "$BOOT/slot.try" ]
	then
		slotlog "trial ${trial} discarded: slot.try could not be deleted"
		trial=
	fi
fi

recovery_requested=
if [ -e "$BOOT/recovery" ]
then
	recovery_requested=1
fi

slotlog "trusted=${trusted} trial=${trial:-none} recovery=${recovery_requested:-no}"
# --- end slot selection ---
```

Create `tools/abslots/init-mount-dispatch.inc`:

```sh
# Device names, written here by the build so that no path in the initramfs
# computes a device from a partition number. In this layout p3 is a root
# filesystem, and S01fs used to run mkfs.exfat on p3.
SLOT_A=/dev/mmcblk0p2
SLOT_B=/dev/mmcblk0p3
RECOVERY=/dev/mmcblk0p5

# One mount attempt, with the single e2fsck retry this script has always had.
mount_fs() {
	mount -o rw "$1" /realroot && return 0
	slotlog "mount $1 failed rc=$?, running e2fsck"
	e2fsck -fvp "$1"
	slotlog "e2fsck $1 rc=$?"
	mount -o rw "$1" /realroot
}

slot_device() {
	case "$1" in
		a) echo "${SLOT_A}" ;;
		b) echo "${SLOT_B}" ;;
		recovery) echo "${RECOVERY}" ;;
		/dev/*) echo "$1" ;;
		*) echo "" ;;
	esac
}

bootdev=

# Rung 1: an explicit recovery request wins over everything.
if [ -n "${recovery_requested}" ]
then
	mount_fs "${RECOVERY}" && bootdev="${RECOVERY}"
fi

# Rung 2: the trial, if there is one and it was disarmed.
if [ -z "${bootdev}" ] && [ -n "${trial}" ]
then
	dev=$(slot_device "${trial}")
	if [ -n "${dev}" ]
	then
		mount_fs "${dev}" && bootdev="${dev}"
	else
		slotlog "trial ${trial} is not a slot name"
	fi
	[ -z "${bootdev}" ] && slotlog "trial ${trial} did not mount"
fi

# Rung 3: the trusted slot.
if [ -z "${bootdev}" ]
then
	dev=$(slot_device "${trusted}")
	[ -n "${dev}" ] || dev="${SLOT_A}"
	umount /realroot 2>/dev/null
	mount_fs "${dev}" && bootdev="${dev}"
	[ -z "${bootdev}" ] && slotlog "trusted ${trusted} did not mount"
fi

# Rung 4: recovery, which runs almost nothing and so can fail almost nowhere.
if [ -z "${bootdev}" ]
then
	umount /realroot 2>/dev/null
	slotlog "falling back to recovery"
	mount_fs "${RECOVERY}" && bootdev="${RECOVERY}"
fi

# Rung 5: expose the card over USB and stop.
if [ -z "${bootdev}" ]
then
	msc
fi

slotlog "booted ${bootdev}"
```

```sh
#!/bin/sh
# Operator tool for the A/B/recovery slots.
#
#   slot status
#   slot install <a|b|recovery> <image>
#   slot try <a|b>
#   slot confirm
#   slot revert
#   slot recovery
#
# SLOT_CONF, BOOT and RUNNING_SLOT are overridable so the tests can drive this
# against loop files instead of a card.
SLOT_CONF=${SLOT_CONF:-/etc/nanokvm-slots.conf}
BOOT=${BOOT:-/boot}

[ -f "$SLOT_CONF" ] || { echo "slot: no $SLOT_CONF"; exit 1; }
. "$SLOT_CONF"

die() { echo "slot: $*" >&2; exit 1; }

device_of() {
	case "$1" in
		a) echo "$SLOT_A" ;;
		b) echo "$SLOT_B" ;;
		recovery) echo "$RECOVERY" ;;
		*) echo "" ;;
	esac
}

running_slot() {
	[ -n "$RUNNING_SLOT" ] && { echo "$RUNNING_SLOT"; return; }
	dev=$(awk '$2 == "/" { print $1; exit }' /proc/mounts)
	case "$dev" in
		"$SLOT_A") echo a ;;
		"$SLOT_B") echo b ;;
		"$RECOVERY") echo recovery ;;
		*) echo unknown ;;
	esac
}

trusted_slot() {
	[ -e "$BOOT/slot" ] || { echo a; return; }
	read t < "$BOOT/slot"
	[ -n "$t" ] && echo "$t" || echo a
}

cmd_status() {
	printf '%-10s %s\n' running  "$(running_slot)"
	printf '%-10s %s\n' trusted  "$(trusted_slot)"
	printf '%-10s %s\n' trial    "$( [ -e "$BOOT/slot.try" ] && cat "$BOOT/slot.try" || echo none )"
	printf '%-10s %s\n' prev     "$( [ -e "$BOOT/slot.prev" ] && cat "$BOOT/slot.prev" || echo none )"
	printf '%-10s %s\n' recovery "$( [ -e "$BOOT/recovery" ] && echo requested || echo no )"
}

cmd_install() {
	name=$1
	image=$2
	[ -n "$name" ] && [ -n "$image" ] || die "usage: slot install <a|b|recovery> <image>"

	dev=$(device_of "$name")
	[ -n "$dev" ] || die "$name is not a slot"
	[ "$name" = "$(running_slot)" ] && die "refusing to install onto the running slot"
	[ -f "$image" ] || die "no such image: $image"

	isize=$(wc -c < "$image")
	# blockdev first: wc -c on a block device reads every byte of it to count
	# them, which is a full 2GB read before the install has written anything.
	# The wc fallback is for the tests, which drive this against plain files.
	dsize=$(blockdev --getsize64 "$dev" 2>/dev/null || wc -c < "$dev")
	[ "$isize" -le "$dsize" ] || die "image is $isize bytes, $dev holds $dsize"

	before=$(sha256sum "$image" | cut -d' ' -f1)
	echo "slot: writing $image to $dev"
	dd if="$image" of="$dev" bs=1M conv=fsync 2>/dev/null
	after=$(dd if="$dev" bs=1M count=$(( (isize + 1048575) / 1048576 )) 2>/dev/null | head -c "$isize" | sha256sum | cut -d' ' -f1)
	[ "$before" = "$after" ] || die "read-back mismatch on $dev"
	echo "slot: $name installed and verified"
}

cmd_try() {
	name=$1
	[ -n "$(device_of "$name")" ] || die "usage: slot try <a|b>"
	printf '%s\n' "$name" > "$BOOT/slot.try"
	sync
	echo "slot: $name will be tried once on the next boot"
}

cmd_confirm() {
	now=$(running_slot)
	[ "$now" = unknown ] && die "cannot tell which slot is running"
	[ "$now" = recovery ] && die "recovery does not promote itself"
	[ -e "$BOOT/slot" ] && cp "$BOOT/slot" "$BOOT/slot.prev"
	printf '%s\n' "$now" > "$BOOT/slot"
	sync
	echo "slot: $now confirmed"
}

cmd_revert() {
	[ -e "$BOOT/slot.prev" ] || die "no previous slot recorded"
	cp "$BOOT/slot.prev" "$BOOT/slot"
	sync
	echo "slot: reverted to $(cat "$BOOT/slot")"
}

cmd_recovery() {
	: > "$BOOT/recovery"
	sync
	echo "slot: the next boot is recovery; remove $BOOT/recovery to leave it"
}

case "$1" in
	status)   cmd_status ;;
	install)  shift; cmd_install "$@" ;;
	try)      shift; cmd_try "$@" ;;
	confirm)  cmd_confirm ;;
	revert)   cmd_revert ;;
	recovery) cmd_recovery ;;
	*) echo "Usage: slot {status|install <slot> <image>|try <slot>|confirm|revert|recovery}"; exit 1 ;;
esac
```

And on success it confirms, so a trial slot promotes itself without anyone remembering to:

```sh
			if healthy; then
				log "reachable after ${waited}s; confirming and standing down"
				slot confirm >> "$LOG" 2>&1
				exit 0
			fi
```

- [ ] **Step 4: Run the test to watch it pass**

```bash

```

Expected: `all cases passed`.

- [ ] **Step 5: Commit**

```bash
chmod +x tools/abslots/device/S00awatchdog tools/abslots/device/test-watchdog.sh
git add tools/abslots/device/S00awatchdog tools/abslots/device/test-watchdog.sh
git commit -m "Give the watchdog a carrier rule and let it confirm a trial

The old rule was net_up AND (web_up OR ssh_up), and net_up needed carrier, so an
unplugged cable rebooted the board into recovery where the cable was still
unplugged. No carrier now stands down: an external fault is not a slot fault.

healthy() is also what `slot confirm` calls, so reachable has one definition
rather than two that drift. On success the watchdog confirms the running slot,
which is what removes the 'forgot to confirm' failure the try-once design would
otherwise have."
```
